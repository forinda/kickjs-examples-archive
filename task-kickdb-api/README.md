# task-kickdb-api

The task-management schema (17 tables, 5 Postgres enums, relations) on **kick/db** — `@forinda/kickjs-db` with its Postgres dialect (`@forinda/kickjs-db/pg`). HTTP routes cover users, workspaces and tasks.

- `src/db/schema/` — code-first schema: uuid / varchar / jsonb / timestamp columns, FKs with cascade, unique + named indexes, `pgEnum`, `relations()`.
- `db/migrations/` — generated by `kick db generate`, reviewed, applied by `kick db migrate latest`.
- `src/db/client.ts` — one `pg.Pool` shared by the query client and the migration adapter.
- `src/adapters/db.adapter.ts` — `DbAdapter` registers the client under `DB_PRIMARY` (repositories take `@Inject(DB_PRIMARY)`), reports `postgres` on `GET /health/ready`, and ends the pool on shutdown.
- `src/index.ts` — `kickDbAdapter()` applies pending migrations on boot in development and refuses to start with pending migrations anywhere else.
- `GET /tasks/:id/full`, `/workspaces/:id/full` — relational queries (`db.query.X.findUnique({ with })`) that cancel with `ctx.signal`.

Guide: [kick/db on Postgres](https://kickjs.app/guide/database/get-started-postgres)

## Run

```bash
docker run -d --name kickdb-pg -p 127.0.0.1:5432:5432 \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=app postgres:18-alpine

pnpm install          # or: npm install
cp .env.example .env  # DATABASE_URL matches the container above
pnpm db:migrate       # or: npm run db:migrate
pnpm dev              # or: npm run dev
```

## Endpoints (under `/api/v1`)

| Method | Path                         | Notes                                     |
| ------ | ---------------------------- | ----------------------------------------- |
| GET    | `/users`, `/users/:id`       | List / show users                         |
| POST   | `/users`                     | Create a user                             |
| GET    | `/workspaces`, `/workspaces/:id`, `/workspaces/:id/full`, `/workspaces/owned-by/:userId` | |
| POST   | `/workspaces`                | Create a workspace (`ownerId` required)   |
| GET    | `/tasks?workspaceId=…`       | Tasks in a workspace (400 without the id) |
| GET    | `/tasks/:id/full`            | Task with comments, assignees, labels     |
| POST   | `/tasks`                     | Create a task                             |
| PATCH  | `/tasks/:id/status`          | Update task status                        |

## Tests

`pnpm test` runs without a database; the round-trip test runs when `DATABASE_URL` is set in `.env.test` (copy `.env.test.example`, point it at a migrated database).
